# picture-tcl：截图 → 命令转录

## 这个技能做什么

用户在后端学习 / 实操中经常发 EDA 工具（Innovus / Genus / PT / StarRC / Calibre…）的终端或脚本截图，想要的是**图里到底敲了哪些命令**——一份忠实、可直接复用的命令清单，而不是讲解。本技能把「图片 → 识别 → 整理命令」固化为固定流程：**只转录，不解析**。

## 流程

### 1. 识别（每张图一次）——不猜图，以用户贴的图为准

**铁律：图里有什么，由图决定。** 禁止用对话上下文、工艺常识、命令习惯去「推断」图里的内容——2026-09-28 两次生产事故都是这么来的：凭主题猜出图中根本不存在的命令（如 setNanoRouteMode），被用户当场指出「完全对不上」。看不清、没把握，就问用户，不要输出拼凑结果。

识别路径（按序）：

1. **直接看图**：用户消息里带的图片就是识别对象，自己读。需要更高分辨率时，用 Read 读消息里给出的本地文件路径（如 `/private/tmp/…/images/N.png`）——Read 能看到图片内容。
2. **密集文字截图（终端回显 / 长命令）→ 本地 OCR 交叉校验**：跑 `swift scripts/ocr_vision.swift <图1.png> <图2.png…>`（macOS Vision，离线、不经外部服务）。OCR 输出**原样**作为客观依据，与自己读图交叉对照，一致才交付；大图可请用户裁剪分段。
3. **仍有歧义 → 问用户**：把不确定的行 / 字符列出来请用户确认（「这行是 X 还是 Y」），或请用户裁剪放大重发。禁止挑一个「像样的」交差。

修正与标注规则：

- OCR 个别字符按已知事实修正时（如 `-cel` → `-cell`），**必须明示修正点**并请用户对照原图确认。
- 没把握的字符标〔存疑〕；行尾被窗口截断的照实转录，不补全。
- **停用旧做法**：不要用固定模板反复调 `mcp__4_5v_mcp__analyze_image`——密集终端截图上它会稳定幻觉（重复行 / 省略号 / 行号错乱，四次输出互相矛盾）。仅当图很简单（大字、少行）且用户明确给了 URL 时才可作辅助，且结果必须与直接读图对照。

要点：

- 多张图按用户给出的顺序编号（图 1、图 2…）。
- 带 UCloud 签名的 URL 有 Expires 会过期：识别完若需归档，**立刻** curl 下载，不要拖。

### 2. 整理输出（给用户的回复）

- 每张图一个小节 + 一个 ```tcl 代码块（其他语言按语言标注）。
- 保留原始顺序、注释行（`#===== xxx =====`）、续行符 `\`、大小写、选项与数值——用户要拿去复用，一个字符都不能「顺手美化」。
- 图中因窗口宽度被折断的同一行命令（如 `FILL4BWP40P14` 换行后接 `0`）拼回一行，并在代码块下加注记说明，让用户知道这是转录修复、不是原图如此。
- 回显 / 输出与命令分开列，标注【回显】。
- 发现可疑处（变量定义了却没引用、拼写异常）照实转录，在注记里提示存疑，不要擅自修正。

**边界：不解析命令含义。**「先不用解析指令意思，只需要把指令内容整理出来」是本技能的核心约定；逐条讲解只在用户后续明确要求时才做。

### 3. 归档（可选，仅在用户明确要求时）

用户说「整理到 docs / 归档」才执行。本仓库归档目标固定为 `docs/tcl/`（TCL 脚本收集区），格式照抄同目录既有 picture-tcl 笔记（如 `pt-source-run-pt.md`、`globalnetconnect-vdd-override.md`）：

1. 图片 curl 下载到 `docs/tcl/images/`，kebab-case 描述性文件名，与笔记同主干（如笔记 `pt-source-run-pt.md` ↔ 图 `images/pt-source-run-pt.png`）。
2. 新建 `docs/tcl/<slug>.md`：
   - frontmatter：`title` / `description`（一句话含关键命令）/ `date: YYYY-MM-DD`；
   - H1 = title；头部 blockquote 三行：日期 / 来源：截图识别整理（picture-tcl，N 张截图）/ 阶段（如 STA、Powerplan、Placement）；
   - 正文小节依次：完整脚本（```tcl，去掉提示符的可执行命令）→ 转录注记（编号列表，含折行拼接、存疑处）→ 原图（`![标题](./images/<slug>.png)`）→ 相关笔记；
   - 相关笔记首条链回 `[TCL 脚本](./index.md)`，再链同目录相关脚本页，最后链 `../experience/t12nm/` 下对应阶段笔记（如 `powerplan.md`、`placement.md`）。
3. 命令本身是可 source 的完整脚本时，另存同主干 `.tcl` 文件（如 `pt-source-run-pt.tcl`），并在笔记「完整脚本」小节末尾加一行：`同目录可直接 source 的版本：[<slug>.tcl](/tcl/<slug>.tcl)`。
4. 更新 `docs/tcl/_meta.json`：在两个 `{"type": "dir", ...}` 条目之前追加笔记文件名主干。
5. 更新 `docs/tcl/index.md` 的「脚本列表」：加一行 `- [标题](./<slug>.md)`，位置与 `_meta.json` 中保持一致（默认加在 `./check/…`、`./timing_report/…` 子目录链接之前）。

## 为什么这样设计

- **忠实转录优先于智能修正**：这些命令是用户的实操记录，价值在「当时就是这么敲的」；擅自补全 / 修正会把实操证据污染成想象。
- **识别以图为证，不猜**：猜出来的「识别结果」比「读不出来」危害大得多——用户会直接拿去用。OCR 交叉校验把「我看到的是」变成「机器也读到的是」。
- **命令与回显分离**：回显混进命令清单，用户复制粘贴时会踩错。
- **折断行拼回但留注记**：既要能直接复用，又要让用户能回溯与原图的差异。
- **归档默认关闭**：多数时候用户只是当场要看一眼命令，写文件是有成本的动作，等明确要求再做。

## 红线（出现即停）

- 心里出现「内容大概是 / 应该是 / 从上下文看是……」→ **正在猜**。停：回原图、跑 OCR、或问用户。
- 把推断出来的命令写进代码块且不加存疑标注 → 严禁交付。
- 两次识别结果对不上还想「拼一版合理的」→ 停，换 OCR 交叉校验或请用户裁剪放大重发。
