# picture-tcl：截图 → 命令转录

## 这个技能做什么

用户在后端学习 / 实操中经常发 EDA 工具（Innovus / Genus / PT / StarRC / Calibre…）的终端或脚本截图，想要的是**图里到底敲了哪些命令**——一份忠实、可直接复用的命令清单，而不是讲解。本技能把「图片 → 识别 → 整理命令」固化为固定流程：**只转录，不解析**。

## 流程

### 1. 识别（每张图一次）

对每张图调用 `mcp__4_5v_mcp__analyze_image`（imageSource 传图片 URL），prompt 用下面这个模板（实测识别率高，勿随意改写）：

> 这是一张 EDA 工具（Innovus 等）的终端 / Tcl 脚本截图。请逐行转录图中所有命令行内容，保持原始顺序，不要遗漏任何选项（-xxx）、参数、变量名（$xxx）、通配符和注释行；保留提示符（如 innovus N> 或 %）以便区分命令与回显；工具回显/输出结果（非命令）请单独标注为【回显】。不要解释命令含义，只做忠实转录。

要点：

- 多张图就调用多次，按用户给出的顺序编号（图 1、图 2…）。
- 本地图片文件用 Read 工具看不到内容，必须走 analyze_image 的 URL；用户只给本地文件时，请用户以图片消息重发或提供 URL。
- 带 UCloud 签名的 URL 有 Expires 会过期：识别完若需归档，**立刻** curl 下载，不要拖。

### 2. 整理输出（给用户的回复）

- 每张图一个小节 + 一个 ```tcl 代码块（其他语言按语言标注）。
- 保留原始顺序、注释行（`#===== xxx =====`）、续行符 `\`、大小写、选项与数值——用户要拿去复用，一个字符都不能「顺手美化」。
- 图中因窗口宽度被折断的同一行命令（如 `FILL4BWP40P14` 换行后接 `0`）拼回一行，并在代码块下加注记说明，让用户知道这是转录修复、不是原图如此。
- 回显 / 输出与命令分开列，标注【回显】。
- 发现可疑处（变量定义了却没引用、拼写异常）照实转录，在注记里提示存疑，不要擅自修正。

**边界：不解析命令含义。**「先不用解析指令意思，只需要把指令内容整理出来」是本技能的核心约定；逐条讲解只在用户后续明确要求时才做。

### 3. 归档（可选，仅在用户明确要求时）

用户说「整理到 docs / 归档到某某目录」才执行：

1. 图片 curl 下载到目标目录的 `images/` 子目录，kebab-case 描述性文件名（如 `chipfinish-output-def-gds.png`）。
2. 在目标目录新建笔记，遵循 **云帆-ic** 仓库惯例：
   - kebab-case 文件名；
   - frontmatter：`title` / `description` / 可选 `date`；
   - 头部 blockquote：日期 / 来源：截图识别整理（picture-tcl）/ 阶段；
   - 正文按图分节：小节标题 + 嵌入图片 + `tcl` 代码块 + 转录注记；
   - 文末「相关笔记」链接同目录与相关主题的既有笔记。
3. 更新该目录 `_meta.json`（JSON 数组追加文件名主干，不含扩展名）。
4. 用户没指定目录时按主题对号入座：
   - 体系化笔记 → `docs/guide/`（如 `intro/`、`basics/`，或新建主题子目录）
   - 短文 / 随笔 → `docs/blog/`
   - 命令集合类可放在 `docs/guide/commands/`（不存在则先建并补 `_meta.json`）
   - 拿不准就问。

## 为什么这样设计

- **忠实转录优先于智能修正**：这些命令是用户的实操记录，价值在「当时就是这么敲的」；擅自补全 / 修正会把实操证据污染成想象。
- **命令与回显分离**：回显混进命令清单，用户复制粘贴时会踩错。
- **折断行拼回但留注记**：既要能直接复用，又要让用户能回溯与原图的差异。
- **归档默认关闭**：多数时候用户只是当场要看一眼命令，写文件是有成本的动作，等明确要求再做。
